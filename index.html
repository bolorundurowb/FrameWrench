#overview

Why FrameWrench exists

Built-in ClientWebSocket hides the frame layer. For legacy .NET applications that need explicit Ping/Pong, fragmentation control, or a frame event model, FrameWrench fills a gap no maintained open-source client currently covers for pre-.NET 6 targets.

Frame-level API

Send and receive every opcode — Text, Binary, Continuation, Ping, Pong, and Close — with explicit FIN and fragmentation control.

Ping/Pong correlation

PingAsync registers a FIFO waiter keyed by payload, measures RTT, and handles concurrent pings with identical payloads.

Actionable errors

Stable ErrorCode, RFC links, diagnostic context, and help: suggestions on every failure.

Message-level convenience

SendTextAsync, SendBinaryAsync, and ReceiveMessageAsync when you do not need per-frame handling.

Strict RFC validation

Masked server frames, invalid UTF-8, bad Close codes, and fragmentation violations reported via ProtocolViolationKind.

Logger-agnostic

No ILogger dependency. Wire logging through FrameReceived, exceptions, or your own wrappers.

Who needs FrameWrench?

  • Legacy .NET Framework 4.6.2/4.8 apps requiring frame-level WebSocket control
  • Real-time latency measurement via explicit Ping/Pong with correlation
  • Custom message fragmentation (proprietary streaming protocols on top of WebSockets)
  • Low-level protocol work — trading systems, game clients, telemetry pipelines

Who does not need it?

  • Modern .NET 6+ — use built-in ClientWebSocket or SignalR/gRPC
  • Message-only apps — higher-level libraries are simpler
  • Compression extensions — FrameWrench is a core client with no extension negotiation
  • Server implementations — this library is client-only
AI disclosure: FrameWrench was developed with generative AI assistance. All code, architecture decisions, and documentation were reviewed as part of the development process.
Upgrading from 1.x? Version 2.0 introduces immutable options, result types, and WireCloseStatus. See the migration guide.

#installation

Install FrameWrench

Use one FrameWrenchClient per WebSocket connection.

Add the NuGet package

$ dotnet add package FrameWrench

Pin a version when needed:

$ dotnet add package FrameWrench --version 2.0.0

Add the package reference manually

<ItemGroup>
  <PackageReference Include="FrameWrench" Version="2.0.0" />
</ItemGroup>

Import the namespaces

using FrameWrench;
using FrameWrench.Core;

From source (contributors)

<ProjectReference Include="../path/to/FrameWrench/src/FrameWrench/FrameWrench.csproj" />
$ cd src/FrameWrench && dotnet pack -c Release

#quick-start

Your first WebSocket connection

Connect, send a text message, receive the echo, and close cleanly.

using FrameWrench;
using FrameWrench.Core;

await using var client = new FrameWrenchClient();
ConnectResult connect = await client.ConnectAsync(new Uri("wss://echo.websocket.org"));

await client.SendTextAsync("Hello, World!");

WebSocketMessage message = await client.ReceiveMessageAsync();
Console.WriteLine(message.GetText()); // "Hello, World!"

CloseResult close = await client.CloseAsync(WireCloseStatus.NormalClosure, "bye");
Connection lifecycle: After a close, create a new FrameWrenchClient to reconnect. Unlike HttpClient, instances are not pooled for reuse.

#api-reference

FrameWrenchClient

Construct with new FrameWrenchClient() for defaults or pass FrameWrenchOptions.

Connection

ConnectResult connect = await client.ConnectAsync(
    new Uri("wss://localhost:8080/ws"),
    cancellationToken);

WebSocketState state = client.State;
// None | Connecting | Open | CloseSent | CloseReceived | Closed | Aborted
  • ConnectAsync(Uri, CancellationToken) → ConnectResult.SelectedSubProtocol
  • State — current WebSocketState

Frame-level send

await client.SendFrameAsync(FrameOpCode.Text, payload, isFinal: true);
await client.SendFrameAsync(FrameOpCode.Binary, payload, isFinal: true);

var frame = WebSocketFrame.Binary(data, isFinal: false);
await client.SendFrameAsync(frame);

await client.SendFrameAsync(FrameOpCode.Continuation, moreData, isFinal: true);

Frame-level receive

WebSocketFrame frame = await client.ReceiveFrameAsync(ct);

await foreach (var f in client.ReceiveFramesAsync(ct))
{
    Console.WriteLine(f.OpCode);
    if (f.OpCode == FrameOpCode.Close) break;
}
  • ReceiveFramesAsync is preferred over obsolete GetFrameStream

Event-driven receive

client.FrameReceived += (sender, frame) =>
{
    Console.WriteLine($"[event] {frame.OpCode} len={frame.Payload.Length}");
};

Fires on the receive-pump thread. Keep handlers short and non-blocking.

Message-level API

await client.SendTextAsync("hello");
await client.SendBinaryAsync(bytes);

WebSocketMessage msg = await client.ReceiveMessageAsync(ct);
Console.WriteLine(msg.GetText());

Ping / Pong

PingResult ping = await client.PingAsync(
    payload: new byte[] { 0x01, 0x02, 0x03, 0x04 },
    timeout: TimeSpan.FromSeconds(5),
    ct: cancellationToken);

if (ping.PongReceived)
    Console.WriteLine($"Pong in {ping.Elapsed.TotalMilliseconds:0.0} ms");

Close

CloseResult result = await client.CloseAsync(
    WireCloseStatus.NormalClosure,
    reason: "done",
    ct: cancellationToken);

For application codes (3000–4999), use WebSocketFrame.Close(4000, reason) with SendFrameAsync.

WebSocketFrame

WebSocketFrame.Text("hello");
WebSocketFrame.Text("chunk", isFinal: false);
WebSocketFrame.Binary(bytes);
WebSocketFrame.Continuation(moreBytes, isFinal: true);

WebSocketFrame.Ping(payload);
WebSocketFrame.Pong(payload);
WebSocketFrame.Close(WireCloseStatus.NormalClosure, "bye");
WebSocketFrame.Close(4000, "app-specific");

CloseFrameInfo close = frame.GetCloseInfo();
Close status types: WireCloseStatus is for codes on the wire. WebSocketCloseStatus is for local state only — never send pseudo-codes like 1005 or 1006.

FrameWrenchOptions

var options = FrameWrenchOptions.Create()
    .WithConnectTimeout(TimeSpan.FromSeconds(30))
    .WithExtraHeader("Authorization", "Bearer ...")
    .WithSubProtocol("chat")
    .WithMaxFramePayloadBytes(64 * 1024 * 1024)
    .WithMaxMessagePayloadBytes(64 * 1024 * 1024)
    .WithPingTimeout(TimeSpan.FromSeconds(10))
    .WithCloseHandshakeTimeout(TimeSpan.FromSeconds(5))
    .WithFailOnInvalidIncomingUtf8(true)
    .WithValidateOutgoingMessages(true)
    .WithAutoPing(true)
    .WithKeepAliveInterval(TimeSpan.FromSeconds(20))
    .WithSslProtocols(SslProtocols.Tls12)
    .WithSingleFrameConsumer(true)
    .Build();
ConnectTimeoutDefault 30s — TCP connect and HTTP Upgrade
ExtraHeadersCustom handshake headers; cannot override reserved WebSocket headers
SubProtocolsOffered Sec-WebSocket-Protocol values
MaxFramePayloadBytesPer-frame limit (default 64 MiB)
MaxMessagePayloadBytesReassembled message limit (default 64 MiB)
AutoPingOpt-in keepalive; closes if Pong not received within PingTimeout
ValidateOutgoingMessagesOutbound fragmentation and UTF-8 validation (default true)
FailOnInvalidIncomingUtf8Abort on invalid inbound Text/Close UTF-8 (default true)
SingleFrameConsumerReject a second concurrent receive stream
Options are immutable after Build(). Header names and values must not contain CR, LF, or NUL.

#guides

Fragmentation, Ping/Pong, and threading

Fragmentation (RFC 6455 §5.4)

Sending a fragmented message

await client.SendFrameAsync(FrameOpCode.Text,
    Encoding.UTF8.GetBytes("Part one "),
    isFinal: false);

await client.SendFrameAsync(FrameOpCode.Continuation,
    Encoding.UTF8.GetBytes("Part two "),
    isFinal: false);

await client.SendFrameAsync(FrameOpCode.Continuation,
    Encoding.UTF8.GetBytes("Part three."),
    isFinal: true);

Receiving at the frame level

var buffer = new List<byte>();

await foreach (var frame in client.ReceiveFramesAsync(ct))
{
    if (frame.IsControl) continue;
    buffer.AddRange(frame.Payload.ToArray());
    if (frame.IsFinal)
    {
        var fullText = Encoding.UTF8.GetString(buffer.ToArray());
        buffer.Clear();
    }
}

Ping/Pong correlation

PingAsync registers a FIFO waiter keyed by payload Base64, sends Ping, and completes when a matching Pong arrives.

PingResult ping = await client.PingAsync(
    payload: Encoding.UTF8.GetBytes("probe-1"),
    timeout: TimeSpan.FromSeconds(5));

Auto-Ping keepalive

var opts = FrameWrenchOptions.Create()
    .WithAutoPing(true)
    .WithKeepAliveInterval(TimeSpan.FromSeconds(20))
    .WithPingTimeout(TimeSpan.FromSeconds(8))
    .Build();

Thread safety

SendingConcurrent sends serialised via SemaphoreSlim
ReceivingSingle pump feeds a channel; each frame delivered to one consumer
FrameReceivedFires on pump thread — keep handlers non-blocking
ReceiveMessageAsyncConcurrent callers must coordinate message ordering
Prefer await client.DisposeAsync() over Dispose() when a SynchronizationContext may be present.

#errors

Actionable exceptions

All library exceptions derive from FrameWrenchException.

WebSocketHandshakeExceptionHTTP upgrade failed, non-101 status, bad accept, subprotocol mismatch
WebSocketClosedByPeerExceptionPeer Close during ReceiveMessageAsync
WebSocketProtocolExceptionRFC violation — filter with ProtocolViolationKind
WebSocketStateExceptionOperation invalid for current State
EndOfStreamExceptionTCP closed mid-frame (not a FrameWrenchException)

ProtocolViolationKind

  • MaskedServerFrame, NonZeroRsv, ReservedOpcode
  • FragmentedControlFrame, ControlPayloadTooLarge, PayloadLimit
  • Fragmentation, InvalidUtf8, InvalidCloseStatus, InvalidClosePayload

Example error shape

error[FW-PROTO-MASKED-SERVER-FRAME]: received a masked frame from the server
...
RFC 6455 §5.1 — https://datatracker.ietf.org/doc/html/rfc6455#section-5.1
help:
  → Confirm the URL is a WebSocket endpoint (ws/wss).

Catching exceptions

try
{
    await client.ConnectAsync(uri, ct);
}
catch (WebSocketHandshakeException ex)
{
    Console.Error.WriteLine($"[{ex.ErrorCode}] {ex.StatusLine}");
}
catch (WebSocketProtocolException ex)
{
    Console.Error.WriteLine($"[{ex.ErrorCode}] {ex.Kind}");
}
catch (FrameWrenchException ex)
{
    Console.Error.WriteLine($"[{ex.ErrorCode}]");
    Console.Error.WriteLine(ex.Message);
}
Redaction: error context never includes Authorization, Cookie, or Sec-WebSocket-Key.

#migration

Upgrading from 1.x to 2.0

Immutable options

// Before (1.x)
var options = new FrameWrenchOptions { ConnectTimeout = TimeSpan.FromSeconds(15) };

// After (2.0)
var options = FrameWrenchOptions.Create()
    .WithConnectTimeout(TimeSpan.FromSeconds(15))
    .Build();

Result types

1.x2.0
ConnectAsync(uri)ConnectResult.SelectedSubProtocol
(bool, TimeSpan) from PingAsyncPingResult.PongReceived, Elapsed
CloseAsync then StateCloseResult.HandshakeCompleted, FinalState

Close status codes

// Before: WebSocketFrame.Close(WebSocketCloseStatus.NormalClosure, "bye");
// After:  WebSocketFrame.Close(WireCloseStatus.NormalClosure, "bye");

CloseFrameInfo info = frame.GetCloseInfo();

Behavioral changes

  • Invalid inbound Close status codes abort the connection (RFC §7.4.1)
  • Decoder protocol errors complete the frame channel as WebSocketProtocolException
  • ExtraHeaders cannot override reserved handshake headers

#faq

Frequently asked questions

How is FrameWrench different from ClientWebSocket?

ClientWebSocket exposes reassembled messages only. FrameWrench treats individual frames as first-class — Ping/Pong, fragmentation, and FrameReceived for every opcode.

Can I reuse a client after disconnect?

No. Create a new FrameWrenchClient for each connection.

Does FrameWrench support permessage-deflate?

No. It implements RFC 6455 core without extension negotiation.

Can I use it on .NET 8+?

Yes via netstandard2.0. Modern apps without frame-level needs should prefer built-in ClientWebSocket.

Can multiple threads send frames concurrently?

Yes. Sends are serialised internally. Receives should follow single-consumer patterns.

What close code for application errors?

Registered codes use WireCloseStatus. Application codes (3000–4999) via WebSocketFrame.Close(4000, "reason").
